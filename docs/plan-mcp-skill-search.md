# MCP-поиск по скиллам

Цель: агент вызывает настоящий инструмент поиска по доступным скиллам, затем
читает выбранный скилл. Сейчас Fable 5 содержит только инструкции для выбора.

## Границы и готовность

Одна фича, один PR. Planning-only: до снятия review-gate меняется только этот
план. Затем write-scope: `mcp/`, `.mcp.json`, манифест и упаковщик, тесты/CI,
документация и применимые инструкции Fable 5 с новой модельной оценкой.
БД не меняется; токены, пользовательские запросы и постоянный индекс не храним.
Вне scope: изменение исходного архива, установка сторонних скиллов, исполнение
их команд, веб-поиск, загрузка инструментов Anthropic, merge и production deploy.

DoneWhen: MCP-клиент обнаруживает и вызывает оба инструмента; поиск проверен на
живом каталоге Codex; негативные сценарии и существующие проверки проходят;
пакет запускается из произвольного каталога после установки; PR готов к ревью.

## Контракт и переиспользование

- Поиск: обязательные `query` (пустая строка означает просмотр каталога) и `cwd`
  (абсолютный каталог проекта); `limit` 1–50 и `offset` для порций. Результат:
  ID, имя, описание, путь, scope, pluginId, score, число совпадений и следующая
  порция. Лексический поиск по имени/описанию без внешней модели и embeddings;
  при необходимости агент формулирует запрос на языке описаний скиллов.
- Чтение: `cwd`, `skill_id`, ограниченные `offset`/`limit`. Читается только
  зарегистрированный включённый `SKILL.md`; произвольного `path` в API нет.
- Реюз: формат и настройки доступа берём у Codex. `scripts/package_plugin.py`
  расширяем; существующие проверки архива и Fable сохраняем. Своего каталога,
  YAML-парсера, фонового индексатора и сетевого сервиса не создаём.
- Источники: [пакет плагина](https://developers.openai.com/plugins/build/plugins),
  [нормализация MCP cwd](https://github.com/openai/codex/blob/main/codex-rs/codex-mcp/src/plugin_config.rs),
  [официальный SDK](https://github.com/modelcontextprotocol/typescript-sdk).
  Контракт `skills/list` проверен генератором JSON Schema установленного Codex
  `0.165.0-alpha.1.2` и реальным ответом `skills/list`; фикстура обезличивается.

## Ошибки и проверки

- Пустой результат отличается от недоступного Codex/ошибки каталога/таймаута.
  Повреждённый ответ не превращается в «скиллов нет». Неполный каталог явно
  обозначается; отключённые скиллы исключаются. Порции имеют стабильный порядок.
- Валидируем пустые/длинные запросы, Unicode, `null`, 0, отрицательные и дробные
  лимиты; границы порций; повторяющиеся имена из разных плагинов/областей.
- Чтение: неизвестный или отключённый ID, исчезнувший/бинарный/слишком большой
  файл, изменение ссылки/пути и выход за границы. Контент не исполняется.
- Процессы запускаются без shell, с ограничением времени/вывода; завершение
  запроса и сервера освобождает дочерний процесс. stdout содержит только MCP.
- Проверяем Windows и Linux, запуск вне корня плагина, отсутствие Node/Codex,
  JSON Schema инструментов, `initialize` → `tools/list` → `tools/call`, ошибки
  аргументов, установочный манифест, воспроизводимость bundle и сохранность
  архива. Для живого smoke нужны установленные Node и Codex; CI не притворяется,
  что располагает пользовательским каталогом.
- Edge-matrix: применимы 2/3/5/6/7 (валидация и область чтения), 8/9/10/12
  (изменения каталога, совместимость, отсутствие записей, cleanup), 17/19/20
  (реальный контракт, неизвестные поля, сбои источника). 1/4/11/13–16 не
  применимы: нет записей в БД, HTTP middleware, сроков или миграций. 18 относится
  к регрессиям; новые случаи проверяются тестами до реализации. 21–27 не
  применимы: пользовательского frontend в этой фиче нет.

## Плановое ревью

Три ручных прохода автора, без заявлений об отдельных агентах:
API/совместимость — обязательный `cwd`, живой каталог и порции;
границы доступа — ID вместо пути и только чтение зарегистрированного файла;
QA/упаковка — готовый bundle, негативные тесты, отделение smoke от CI-фикстуры.
Эти уточнения внесены в план; локальных блокеров не осталось.
Внешний plan review-gate ещё не снят: ожидается Codex review для этого PR либо
явное одобрение плана пользователем. После gate реализация идёт в том же PR.
