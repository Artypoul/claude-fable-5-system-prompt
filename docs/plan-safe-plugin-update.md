# Безопасное обновление Fable 5

Цель: обновить установленный плагин с резервной копией и проверкой результата;
при обычной ошибке автоматически вернуть работоспособную предыдущую версию.
Пользователь разрешил реализацию, проверку отката, публикацию и глобальное
обновление. В продолжающейся работе над этим плагином сохраняем его указание
не ждать внешнего ревью. Три ручных прохода плана — ниже.

## Что делаем

| Что делаем | Было | Стало | Как делаем | БД | Endpoint / команда |
| --- | --- | --- | --- | --- | --- |
| Сохранить прежнее состояние | CLI заменяет пакет без нашего бэкапа | До изменений есть копия пакета, config.toml и настроек Fable | Приватный каталог под пользовательским Codex home, SHA-256 файлов, журнал фаз и отдельный recovery runner | БД не меняется | `node mcp/dist/update.mjs update --project <absolute-path>` |
| Подготовить конкретную версию | Обновляется подвижная main | Кандидат проверяется и устанавливается по точному SHA | Git staging из разрешённого репозитория; проверка manifest/build-info; штатные команды marketplace/plugin | БД не меняется | Та же команда, `--ref main` по умолчанию |
| Проверить установленное | Проверка была ручной | Успех только после совпадения файлов, каталога и MCP-вызовов | Native Codex catalogue; настоящий bundled SDK-клиент: tools/list, search_skills, read_skill; проверка настроек | БД не меняется | Автоматический health check |
| Вернуть предыдущую версию | Ручная перестановка | При завершившейся ошибкой установке/проверке восстанавливается прежний пакет | Сохранённая версия; Git pin на прежний SHA, при недоступной сети — локальный пакет из бэкапа; повторная проверка | БД не меняется | Автоматически; также `rollback --backup <path> --project <path>` |
| Восстановить настройки только Fable | Полное восстановление config.toml могло бы стереть чужие правки | Остальные настройки сохраняются | Native `config/read` и `config/batchWrite`, только две таблицы Fable, expectedVersion; полный файл лежит в бэкапе, но целиком не перезаписывается | БД не меняется | Внутренний Codex app-server API |
| Проверить настоящий откат | Downgrade не репетировали | Известно, что старый пакет и настройки реально вернулись | Отдельный тестовый marketplace/plugin namespace; родной CLI и MCP; сломанный кандидат; текущий Fable не переключается | БД не меняется | Интеграционный тест + unit tests и CI |

## Границы и контракт

- Версия плагина 1.3.0; отдельный bundled update runner, Node 20+ и Codex/Git
  в PATH. При первом переходе с 1.2.0 runner запускается из checkout, затем
  доступен в установленном пакете. npm при запуске не требуется.
- CLI предназначен для установленного Fable 5. Snapshot до первого изменения;
  локальные модификации пакета и несогласованные marketplace/cache — явный
  отказ до установки. Резервные копии не удаляются автоматически.
- Снимок содержит конфигурацию пользователя и может содержать секреты:
  хранится локально в приватном каталоге, не печатается, не уходит в GitHub.
- Успех фиксируется только после health check. Источник закрепляется на
  проверенном SHA; следующий безопасный update снова разрешает указанную ref.
  После offline rollback источник может оставаться локальной резервной копией.
- Бэкап полного config.toml — аварийный артефакт. Автоматически восстанавливаем
  только настройки целевого плагина и его marketplace. Конфликт одновременной
  правки настроек, неизвестный исход CLI timeout, сбой самого восстановления
  означают `recovery_required`, а не ложный успешный откат.
- Lock запрещает два наших обновления одновременно; recovery runner и журнал
  сохраняются до мутации. После аварийного завершения следующая команда не
  начинает новое обновление поверх незавершённой транзакции.
- Write-scope: `mcp/`, упаковщик/тесты/CI, версия и документация. Переиспользуем
  существующий SDK, сборщик, MCP health и native Codex API; собственного TOML
  редактора и прямого редактирования внутренних БД Codex не создаём.
- Вне scope: бинарники приложения Codex, проекты пользователя, чужие плагины,
  auth.json, повышение прав, очистка старых бэкапов, произвольный updater других
  плагинов, гарантия восстановления при отказе диска/потере питания.

## Проверки и источники

- Реальные контракты CLI list/add/remove и marketplace list/ref проверены на
  установленном Codex 0.165.0-alpha.1.2. ConfigRead/BatchWrite schema получены
  генератором этого CLI; настоящий config/read подтверждает user layer и version.
  Формат fixtures — обезличенные native ответы, без конфигурации пользователя.
- Тесты: успех, ошибка до мутации, провал установки/health, настоящий downgrade,
  offline fallback, неподходящий/повреждённый бэкап, одновременная запись, lock,
  незавершённая транзакция, недоступный Node/Codex/Git, повторный rollback.
- Проверяем сохранность остальных настроек и отсутствие успешного статуса при
  провале восстановления. Linux CI — детерминированные тесты; реальный CLI
  rollback отдельно выполняется на этой машине с тестовым namespace.
- Edge matrix: 1–3/5–10/12/17–20 применимы (сохранность, частичные состояния,
  scope, гонки, совместимость, cleanup, настоящий контракт, сбой источника).
  4/11/13–16 не применимы: нет HTTP middleware, доменных сроков или миграций БД.
  21–27 не применимы: frontend не меняется.

## Ручное ревью плана

API/совместимость: SHA вместо подвижной версии и повторный health старого пакета.
Сохранность/доступ: scoped config writes с CAS, приватные копии, запрет полного
overwrite и прямых правок внутренних БД. QA/восстановление: отдельный native
namespace, broken candidate, offline path и явный recovery_required.
Эти уточнения внесены; локальных блокеров нет. Внешний review не ожидаем по
сохранённому указанию пользователя. Реализация идёт в этом же PR.

## Реализация и повторное ручное ревью

API/совместимость: штатные plugin/marketplace команды, scoped config API с
expectedVersion, точный SHA; нормализация extended Windows local path
проверена настоящим fallback. Сборка updater запускается отдельно от checkout
без node_modules; адаптер CommonJS встроенных модулей добавлен после красного
bundle-теста. Новые third-party license notices включены.

Сохранность/доступ: пакет и полный config сохраняются до мутации; целостность
пакета, config, recovery runner и snapshot проверяется перед восстановлением.
Секреты не печатаются; полный config не подменяется. Неизвестный исход записи
и конфликт настроек сохраняют блокировку. Проверки места выполняются перед
бэкапом и перед установкой. Сбой записи журнала после установки не блокирует
попытку восстановить проверенную копию.

QA/восстановление: 35 Node-тестов и 54 Python-теста проходят после formatter
и rebuild. Включены повреждение config/runner/metadata, конфликт, живой и
повреждённый lock, недоступная команда, timeout, недостаток места и сбой
журнала после установки. Финальная реальная репетиция после hardening прошла четыре
проверки: Git-откат, offline local fallback, успешное обновление с двумя
ручными откатами, сохранение остальных настроек. Один промежуточный повтор
остановился из-за ENOSPC; после появления свободного места полный повтор
завершился успешно. Текущая рабочая версия 1.2.0 включена; bundled
updater реально отказал с NO_SPACE до мутации при недостаточном запасе.

Edge-review: 1/10 — native сравнение настроек и тесты snapshot; 2/3/5 —
проверка обязательных аргументов, null при снятии только fixture-таблиц,
проверка false/невалидных PID; 6/7 — фиксированный target и отказ от другого
источника, без повышения прав; 8 — lock, CAS, no-blind-retry тесты;
9 — настоящий переход со старого пакета 1.2.0; 12 — auto/manual rollback
и cleanup только fixture-регистрации; 17 — реальный CLI/API/MCP;
18 — bundle и Windows source mismatch сначала дали красный прогон;
19/20 — UNCERTAIN, неизвестный формат и offline source дают явный результат.
Остальные пункты неприменимы по причинам выше. Модельная observation 1.2.0
валидна: инструкции, сценарии и evaluator не изменялись. Нового вызова модели
в этой задаче не было. На текущем diff кодовых блокеров ручного ревью нет.
Linux CI дополнительно обнаружил регистр имени license у path-key: исправлен
поиск реального имени через readdir; проверены чистый npm ci и повторный build.
Перед глобальным обновлением остаётся дождаться CI точного опубликованного SHA.
