# Исправления ревью безопасного обновления 1.3.1

Релиз 1.3.2 закрывает два подтверждённых P2. Пользователь разрешил исправление,
регрессии, реальные update/rollback, публикацию и глобальное обновление.
Сохраняется его указание не ждать внешнего review; план проверен вручную.

## Что делаем

| Что делаем | Было | Стало | Как делаем | БД | Endpoint / команда |
| --- | --- | --- | --- | --- | --- |
| Снять старую блокировку одним процессом | Два rollback могут удалить новую блокировку друг друга | Не более одного восстановления одновременно | Отдельный exclusive recovery-claim.json на короткую секцию read/check/unlink/acquire; затем прежний active.json | БД не меняется | Прежний rollback --backup --project |
| Проверить происхождение пакета | Одинаковые локальные правки в marketplace/cache принимаются за HEAD | До бэкапа проверяется точное содержимое Git-коммита | git ls-tree точного SHA; Git blob hash сырых файлов и SHA-256 сохранённого inventory, включая список файлов | БД не меняется | Прежний update --project |
| Восстановить старые нестандартные бэкапы | Успешный Git install с другими байтами не вызывает local fallback | Восстанавливается проверенная локальная копия | Проверить Git-копию до выбора источника; mismatch направить в существующий local/Windows recovery | БД не меняется | Автоматически и manual rollback |
| Подтвердить поведение | Найденные сценарии не покрыты | Красные регрессии на 1.3.1, зелёные после исправлений | Контролируемое конкурентное расписание; настоящие Git-объекты; native CLI/MCP и автономный runner | БД не меняется | npm test; native-update.mjs; production rehearsal |

## Границы и состояния

- Сохраняем CLI, snapshot schema, старые бэкапы, scoped config API и MCP.
  Не меняем инструкции скилла, исходный архив, модельную observation или чужие
  плагины. Не завершаем процессы Codex/MCP. Новых runtime-зависимостей нет.
- Порядок rollback: короткий recovery claim → проверка stale active → захват
  active → освобождение claim → восстановление. Update по-прежнему берёт
  active; если он успеет первым, rollback откажет, не удаляя новый active.
- Если процесс оборвётся внутри короткой секции и оставит claim, следующий
  rollback откажет с UPDATE_LOCKED; автоматического небезопасного удаления
  claim нет. Нужен разбор владельца, как для повреждённого lock.
- Точный Git SHA связывается с байтами, а не с Git status: assume-unchanged,
  совпадающие локальные правки, добавленные/удалённые файлы не обходят проверку.
  Неподдерживаемые Git modes отклоняются. Чистая Git-установка проходит.
- Для старого бэкапа mismatch после Git install использует local snapshot;
  UNCERTAIN и SETTINGS_CONFLICT по-прежнему не повторяют мутации вслепую.

## Проверки и ручное ревью

API/совместимость: интерфейсы неизменны, проверяется старый snapshot и Windows
recovery slot. Сохранность: claim атомарен, захвачен и освобождён до restore;
Git-копия не считается правильной без проверки файлов. QA: тесты сначала
показывают оба старых дефекта; проверяем конкуренцию, cleanup claim при отказе,
старый повреждённый Git baseline, clean/dirty/assume-unchanged Git, native
update/rollback и сохранность прочих настроек. Локальных блокеров плана нет.

Edge matrix: 1/10 — байты и настройки; 2/3/5 — прежняя валидация, отсутствующий
и повреждённый lock; 6/7 — фиксированный plugin/profile scope; 8/13 — claim
перед active, реальный конкурентный тест; 9/11/12/16 — старые snapshot и
update→rollback→update; 17 — настоящие Git/CLI/MCP; 18 — красные тесты до кода;
19/20 — fail-closed при conflict/unknown и local fallback. 4/14/15 и 21–27
неприменимы: нет middleware, доменных сроков, миграций БД или frontend.

## Реализация и повторное ручное ревью

Оба P2 воспроизведены до правки: конкурентный тест показал два restore,
четыре варианта совпадающих локальных правок были приняты, старый бэкап не
получил local fallback. После formatter/rebuild проходят 44 Node + 54 Python.
ZIP и source validator проходят; исходный архив, .agents/skills, MCP-поиск и
модельная observation не менялись. Настоящая расширенная репетиция описана
в PR отдельно от детерминированных тестов.

API/совместимость: старый snapshot остаётся читаемым, Git mismatch направлен
в существующие local/Windows recovery пути. Сохранность: claim берётся через
exclusive create и освобождается в finally до restore; чужой новый active
не удаляется. При зависшем claim применяется явный fail-closed. QA: семь
первых красных регрессий стали зелёными; clean Git с бинарными blob проходит,
modified/assume-unchanged/untracked/deleted — отказ до установки. Повторное
ревью текущего diff тремя ручными ролями не оставило кодовых блокеров.

Edge evidence: 1/10 — legacy customized backup и полное сравнение файлов;
2/3/5 — malformed/live active и existing claim; 6/7 — неизменный target scope;
8/13 — controlled ABA race и native конкурирующие rollback; 9/11/12/16 —
совместимость snapshot/local recovery и native update→rollback→update;
17 — настоящий Git, CLI/MCP в native тесте; 18 — зафиксированный красный прогон;
19/20 — UNKNOWN/CONFLICT без слепого retry и Git mismatch → local snapshot.
