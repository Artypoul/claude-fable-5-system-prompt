# Поиск и чтение скиллов через MCP

Плагин содержит локальный stdio-сервер `fable5_skills` для чтения инструкций.
Версия **1.4.3** явно отделяет найденные файлы кэша от подтверждённого нативного
состояния сессии. Нужен Node.js 20+; нативная установка и отдельные проверки
обновлятора требуют совместимый Codex CLI. Внутренний API Codex experimental
и может измениться. Правила выбора каталога версии сверены с исходниками
Codex `0.167.1`; это не заявление о выполненной активации в пользовательской сессии.
Собранный SDK включён в `mcp/dist/server.mjs`: установка npm-зависимостей нужна
только разработчику. При запуске сервер ничего не скачивает и не открывает порт.

## Инструменты

`search_skills` принимает `query`, абсолютный `cwd` проекта, `limit` (1–50,
по умолчанию 10) и `offset` (по умолчанию 0). Пустой запрос перечисляет каталог;
остальные запросы ищут по имени и описанию, с нормализацией Unicode и регистра.
Это лексический поиск без embeddings и отдельного вызова модели. Результат
содержит `skills`, `total`, `next_offset`, `catalog_sha256`, `partial`,
`warning_count`, `source_warning_count`, `warnings`, `catalog_source` и
`native_context_verified`. Каждая запись содержит `enabled_in_native_context`:
для кандидата из кэша это `null`, а не подтверждение включения в Codex.
При изменении отпечатка между страницами начните просмотр снова.

`read_skill` принимает `cwd`, `skill_id` из поиска, `offset` и `limit` текста
(по умолчанию 16000, максимум 32000 символов Unicode). Возвращает `content`,
`total_chars`, `next_offset` и SHA-256 полного файла. Максимальный SKILL.md —
1 MiB. Каждая страница сохраняет сведения об источнике, предупреждениях и
неподтверждённом нативном контексте. Произвольного `path` в аргументах нет;
каталог повторно читается перед каждым запросом. Отключённые в прочитанном
базовом профиле скиллы исключаются; включение в других слоях конфигурации этим
источником не подтверждается. Старый ID не позволяет прочитать файл, который
больше не входит в текущий набор кандидатов. Ссылки на файл SKILL.md отвергаются; symlink на
сам каталог скилла допускается. Текст не исполняется и не активирует скилл
нативным механизмом Codex; модель получает его как результат инструмента.

`fable-status` принимает только абсолютный `cwd` и выполняет read-only проверку
полного gateway: ровно один включённый Fable plugin из `fable5-codex@fable5`
или `fable5-codex@gigma-skills`, а также
`using-superpowers` и `writing-plans` из `superpowers@gigma-skills`. Проверяются
уникальность записей, native namespaced имена, `partial`, предупреждения,
зарегистрированные пути и стабильный SHA-256 каждого SKILL.md. Инструмент
может вернуть `status: "ready"` только для подтверждённого нативного контекста
вызывающей сессии после всех проверок и не вызывает
установку, обновление или выполнение плагинов. Неизвестный источник или две
включённые копии Fable блокируют готовность. Выбранные identity, путь и digest
должны совпадать в поиске, чтении и статусе. Каталог из кэша, неизвестный источник
или каталог отдельного дочернего Codex не удовлетворяют проверке контекста,
даже если все файлы читаются и счётчики предупреждений были очищены.

## Источник и ограничение готовности

По умолчанию сервер читает файлы профиля и выбранного кэша напрямую, без запуска
Codex и обновления marketplace. Источник обозначается `configured_cache`.
Он не наблюдает полную эффективную конфигурацию вызывающей сессии: проектные,
профильные, session и managed-настройки могут менять доступность плагинов.
Поэтому результат всегда содержит `native_context_verified: false`,
`partial: true` и предупреждение `NATIVE_CONTEXT_UNVERIFIED`.
`source_warning_count` отдельно считает реальные ошибки чтения каталога;
`warning_count` также включает предупреждение о неизвестном контексте.

Поиск и чтение кандидатов остаются доступны для явно разрешённой частичной
проверки исходников. `fable-status` для этого источника возвращает
`PIPELINE_INCOMPLETE`. Пакет пока не содержит адаптер, получающий подтверждённый
контекст той же сессии Codex, поэтому стандартный сервер **не проходит native
activation gate**. Параметра инструмента или переменной окружения, позволяющих
объявить контекст подтверждённым, нет. Для отдельно выбранного режима
`chatgpt_github` действуют его собственные проверки закреплённых источников.

При выборе файлов приоритет имеет каталог версии `local`. Повреждение
выбранного каталога не приводит к молчаливому чтению другой версии.
Неподдерживаемая или неоднозначная комбинация версий даёт ошибку источника.

Существующая вспомогательная функция `fetchNativeCatalog` запускает отдельный
`codex app-server --stdio` и вызывает `skills/list` с `forceReload: true`.
Она используется отдельными нативными проверками, а не стандартным MCP-поиском.
Её источник `native_subprocess` не подтверждает контекст вызывающей сессии.
Процесс ограничен 15 секундами и 8 MiB вывода. `FABLE5_CODEX_BIN` задаёт путь к
CLI там, где применяется этот вспомогательный процесс; shell-команда не поддерживается.

Обновлятор отдельно проверяет, что Codex загрузил установленный файл с ожидаемым
путём и SHA-256. После этого его проверка здоровья пакета может принять MCP-чтение
с единственным известным предупреждением о контексте и без ошибок источника.
Старые полные ответы MCP также поддерживаются для проверки отката. Это проверка
пакета и чтения его байтов; исключение не позволяет получить native `ready`.

Сбой источника возвращается с `isError: true` и кодом ошибки; это отличается от
успешного поиска с `total: 0`. Ошибки отдельных скиллов обозначаются `partial` и
счётчиком предупреждений. Сырые сообщения конфигурации/секреты не возвращаются.

## Проверка

После обычного обновления плагина начните новый чат или перезагрузите клиент,
если каталог инструментов текущего чата не обновился. Агент должен обнаружить
реальные `search_skills` и `read_skill` в пространстве имён плагина.

Для прямой проверки настоящим SDK-клиентом, без вызова модели:

```sh
cd mcp
npm ci --ignore-scripts
npm run build
npm test
npm run smoke -- /absolute/project/path
```

Smoke вызывает собранный сервер, ищет Fable 5, читает найденный файл и затем
требует успешную нативную проверку. Со стандартным источником `configured_cache`
последний шаг завершается `PIPELINE_INCOMPLETE`; успешное чтение не скрывает этот
результат. Тесты CI проверяют этот отказ и отдельно используют явно синтетический
подтверждённый каталог для положительных сценариев. Фикстура не является
доказательством активации в пользовательской сессии.

Конфигурация `.mcp.json` использует `command: node`, относительные аргументы и
`cwd: ./`; Codex разрешает cwd относительно установленного корня плагина.
Поэтому перемещение кэша не требует правки абсолютных путей. Если Node не в
PATH клиента, настройте окружение запуска клиента до включения этого сервера.

SDK и его лицензии включены в bundle; `mcp/dist/THIRD_PARTY_LICENSES.txt`
содержит условия сторонних компонентов. CI пересобирает артефакт и сверяет его
с репозиторием. Упаковщик проверяет отпечатки исходников и сборки.
