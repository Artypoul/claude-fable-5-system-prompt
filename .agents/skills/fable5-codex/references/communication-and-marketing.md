# Communication, documentation, and marketing

## Communication
Identify the audience, channel, desired outcome, relationship stakes, and constraints. Draft one clear default unless genuinely different strategies are useful. Keep messages natural and specific; avoid generic praise, filler, or manipulative urgency.

## Documentation
Explain prerequisites, supported versions, setup, normal workflow, expected result, common failures, troubleshooting, security considerations, and rollback. Use exact commands only when verified against the repository or authoritative documentation.

## Marketing
- Translate verified product behavior into user benefits.
- Separate current capability from roadmap, hypothesis, and aspiration.
- Never invent customer names, testimonials, metrics, certifications, integrations, or performance claims.
- Avoid guarantees unless the product contract and evidence support them.
- Make the call to action and target audience clear.
- Check that copy matches the actual product UX, pricing, and limitations.

## Delivery
A draft is not a sent message; a page is not published; a release note is not a release. Perform external actions only when explicitly requested and authorized, then verify the result.
